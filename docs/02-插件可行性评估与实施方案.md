# Vortex「管理器内浏览 / 下载 Nexus MOD」插件 —— 可行性评估与实施方案

> 关联文档：`Vortex插件开发接口与方法.md`（同目录，接口细节见该文）
> 评估对象：Vortex **2.8.2**（`E:\Game\Vortex` 实测）、Nexus Mods **GraphQL v2**
> （`nexus_api\docs\NexusMods-GraphQL-API-完整参考.md`，下称《GraphQL 参考》）
> 撰写时间：2026-10

## 0. 一页结论

**结论：可行。** 你设想的「不打开浏览器 → 用 Nexus 的 Web API 搜索 → 直接把结果交给 Vortex 下载」这条链路，
每一段都有官方支持：

| 环节 | 官方支持 | 关键依据 |
| --- | --- | --- |
| 在管理器里加一个「浏览 MOD」页面 | ✅ 一等公民 | `context.registerMainPage(...)`；官方内置的 **Browse Nexus**（合集浏览）就是同一套写法 |
| 调 Nexus Web API 搜索 MOD | ✅ 有现成 GraphQL | `POST https://api.nexusmods.com/v2/graphql` 的 `mods(filter/sort/offset/count)` |
| 在扩展里发 HTTP（不受浏览器 CORS 限制） | ✅ | 主窗口 `nodeIntegration: true`、`contextIsolation: false`，扩展可用 Node `https` / `electron.net` |
| 拿到用户已登录的 Nexus 凭据 | ✅ | `state.confidential.account.nexus.APIKey`（官方页面组件自己就这么读） |
| 把下载交给 Vortex | ✅ | `emit('start-download', [nxm://…])` → 内置 `NxmProtocol` 解析 → 下载队列 |
| 下载后自动安装成 Mod | ✅ | `emit('start-install-download', dlId, { allowAutoEnable: true }, cb)` |

**但有 4 条硬约束，必须在产品设计阶段就接受：**

1. **不能自己拼下载直链。** Nexus 的下载 URL 是按账号/会员实时签发、带过期签名的；
   GraphQL 里根本没有「取 mod 文件下载地址」的查询（`ModFile.uri` 只是路径片段，
   `signedDownloadUrl` 是 staff 专用）。正确做法是只传 `nxm://<domain>/mods/<modId>/files/<fileId>`，
   让 Vortex 自己的下载管道去换链接。
2. **免费用户做不到「一键静默下载」。** 免费账号必须经过官网授权跳转 —— Vortex 会打开**系统默认浏览器**
   到 `…?tab=files&file_id=<fid>&nmm=1`（`nmm=1` = 走「Download with Vortex」回传），用户在页面点一次再回到 Vortex。
   这不是插件能绕过的，**只能优化文案与流程**。Premium 用户才是真正的「一键」。
3. **API 是 WIP。** 官方明示「可能在不通知的情况下变更/移除」，必须把网络层做成可替换的一层，并对所有错误兜底。
4. **不能把用户的 API Key 发给任何第三方服务器。** 请求必须由本机直连 `api.nexusmods.com`。

**建议的产品定位**：一个「Nexus 浏览器 Lite」——搜索/筛选/详情/文件列表 + 一键下载安装，
**不做**站点镜像、不做自动更新、不做全站爬取。这样工作量可控（预估 2～3 周单人 MVP），合规风险最低。

## 1. 需求拆解

你的原始设想可以拆成 5 个可独立验证的能力：

```
┌─ A. 游戏上下文  ─ 当前激活的是哪个游戏？对应 Nexus 的哪个 domain / gameId？
├─ B. 搜索        ─ 关键词、排序、分页、筛选（分类/标签/成人内容）
├─ C. 详情        ─ 描述、作者、版本、图、依赖、文件列表（哪个是主文件？）
├─ D. 下载        ─ 选定文件 → 交给 Vortex 下载队列（进度/断点/校验由 Vortex 负责）
└─ E. 安装        ─（可选）下载完自动安装/启用，落到 Mods 表
```

A、B、C 是纯查询（只读），D、E 是写操作（但写的是 Vortex 的队列，不是 Nexus）。

## 2. 逐项可行性论证

### 2.1 A｜游戏上下文：能不能知道「用户在管哪个游戏」

**✅ 可以，而且很干净。**

```ts
const gameId = activeGameId(state);                     // 内部 id，如 "skyrimse"
const domain = nexusGameId(getGame(gameId), gameId);    // Nexus 域名，如 "skyrimspecialedition"
```

- `nexusGameId()` 是官方 `util` 导出的转换函数（`src/api.ts` → `util`）；
- 反向转换用 `convertGameIdReverse(knownGames(state), gameId)`；
- 内置 `browse_nexus` 页面第一件事就是这个（源码 `BrowseNexusPage.tsx:87-92`），说明这条路被官方生产验证过。

**注意**：内部 id ≠ Nexus 域名。项目里必须**全程区分**这两个值：
搜索用 domain（`filter.gameDomainName`），下载 `modInfo.game` 用内部 id。混淆是最常见的 bug 源。

### 2.2 B｜搜索：Nexus 有没有「搜索 MOD」的 API

**✅ 有，就是 GraphQL 的 `mods` 查询**（《GraphQL 参考》R1/R2）。

```graphql
query SearchMods($filter: ModsFilter, $sort: [ModsSort!], $offset: Int, $count: Int) {
  mods(filter: $filter, sort: $sort, offset: $offset, count: $count) {
    totalCount
    nodes {
      modId
      uid
      name
      summary
      version
      downloads
      endorsements
      adultContent
      createdAt
      updatedAt
      pictureUrl
      game { id domainName }
      uploader { memberId name }
    }
  }
}
```

```json
{
  "filter": {
    "op": "AND",
    "filter": [
      { "gameDomainName": [{ "value": "skyrimspecialedition", "op": "EQUALS" }] },
      { "nameStemmed":     [{ "value": "weather",              "op": "WILDCARD" }] }
    ]
  },
  "sort": [{ "endorsements": { "direction": "DESC" } }],
  "offset": 0,
  "count": 24
}
```

要点（全部来自实测文档）：

- **必须用 POST**，GET 会 404；错误是 HTTP 200 + `errors[]`，**不能只看状态码**；
- 名称模糊匹配优先 `nameStemmed` + `WILDCARD`；`name` 只适合 `WILDCARD`（区分标点）；
- 可用筛选字段很丰富：`categoryName`、`tag`、`author`、`adultContent`、`supportsVortex`、
  `directDownloadEnabled`、`downloads`/`endorsements` 数值比较（`ModsFilter` 有 20+ 字段）；
- 排序键：`relevance` / `downloads` / `endorsements` / `createdAt` / `updatedAt` / `name` / `random`（可带 seed）；
- `count` 建议 ≤ 50；
- **成人内容**：`mods` 查询默认会按站点偏好过滤，需要显式 `adultContent` 过滤 + 读用户偏好
  （`state.persistent.nexus.userInfo.adult`）来决定是否提示；
- 分面（facets）可用于做左侧「分类/标签」筛选栏，但返回量较大，MVP 可以后置。

**替代方案（无需自己发请求）**：`api.ext.nexusGetLatestMods` / `nexusGetTrendingMods` 只能拿「最新/热门」，
**没有关键词搜索**。所以「搜索」必须自己调 GraphQL —— 这也是本项目唯一绕不开的「自建网络层」。

### 2.3 网络：扩展里发请求会不会被 CORS 拦

**⚠️ 用 `fetch` 会被拦；用 Node/Electron 网络模块不会。**

事实（来自 2.8.2 的 `main.cjs` 窗口配置）：

```js
webPreferences: {
  preload, nodeIntegration: true, nodeIntegrationInWorker: true,
  webviewTag: true, contextIsolation: false, backgroundThrottling: false
}   // 没有 webSecurity: false → 默认 true，渲染进程的 fetch 受同源策略约束
```

而 `index.html` 的 CSP 只限制 `script-src`，没有 `connect-src`，所以 CSP 不是障碍，**CORS 才是**。
《GraphQL 参考》§2.7 也明确说：*「该端点用于服务端/桌面客户端调用……不建议浏览器直连」*。

**正确做法**：扩展里用 Node 的 `https`（或 `electron.net.request`）发请求：

```ts
import * as https from "https";

function graphql<T>(query: string, variables: unknown, apiKey?: string): Promise<T> {
  const body = JSON.stringify({ query, variables });
  return new Promise((resolve, reject) => {
    const req = https.request({
      hostname: "api.nexusmods.com",
      path: "/v2/graphql",
      method: "POST",
      headers: {
        "Content-Type": "application/json",
        "Content-Length": Buffer.byteLength(body),
        ...(apiKey ? { apikey: apiKey } : {}),
      },
    }, (res) => {
      const chunks: Buffer[] = [];
      res.on("data", (c) => chunks.push(c));
      res.on("end", () => {
        const text = Buffer.concat(chunks).toString("utf8");
        try {
          const json = JSON.parse(text);
          if (json.errors?.length) {
            return reject(Object.assign(new Error(json.errors[0].message), {
              code: json.errors[0].extensions?.code, errors: json.errors,
            }));
          }
          resolve(json.data as T);
        } catch (e) { reject(new Error(`bad json: ${text.slice(0, 200)}`)); }
      });
    });
    req.on("error", reject);
    req.write(body);
    req.end();
  });
}
```

> 为什么不用 `fetch`：即使主窗口 `webSecurity` 将来被关掉，`fetch` 也拿不到 `apikey` 头所需的
> 预检豁免；Node 层则完全不受同源策略约束，且能设置自定义头。

### 2.4 认证：API Key 从哪来，要不要用户再填一次

**✅ 不用用户再填。Vortex 已经把 Key 存在 state 里了。**

```ts
const nexus = state.confidential?.account?.["nexus"];
const apiKey = nexus?.APIKey;            // 已登录时存在
const oauth  = nexus?.OAuthCredentials;  // 新登录方式
const isLoggedIn = !!(apiKey || oauth);
```

这是官方 `BrowseNexusPage.tsx:90-93` 的原样逻辑。

- Key 只存在内存变量里，**不写日志、不落盘、不发第三方**；
- 未登录也能搜索（GraphQL 大部分查询匿名可调），但：成人内容受限、`preferences` 等接口报 `UNAUTHORIZED`、
  个性化数据为空；
- 想让用户登录，直接 `api.ext.ensureLoggedIn?.()` 或 `emit('request-nexus-login')`；
- **认证自检探针**：查一次 `{ preferences { adult } }`，能返回即代表 key 生效（《GraphQL 参考》§1.2）。

### 2.5 C｜详情与文件列表

**✅ 都有现成查询。**

```graphql
query ModDetail($modId: ID!, $gameId: ID!) {
  mod(modId: $modId, gameId: $gameId) {
    modId uid name summary description version author category
    downloads endorsements fileSize adultContent directDownloadEnabled supportsVortex
    createdAt updatedAt pictureUrl
    game { id domainName name }
    uploader { memberId name avatar }
    viewerDownloaded viewerEndorsed viewerTracked
  }
}

query ModFiles($modId: ID!, $gameId: ID!) {
  modFiles(modId: $modId, gameId: $gameId) {
    fileId uid name version category primary manager size sizeInBytes uri date
  }
}
```

- `mod(modId, gameId)` **两个参数都必须给**（modId 只在游戏内唯一）；
- `modFiles` 里 `category: 1` 是主文件，`primary: 1` 同理；`sizeInBytes` 是 `BigInt`，**JSON 里是字符串**；
- 也可以完全不用 GraphQL，改用官方封装：`api.ext.nexusGetModInfo(gameId, modId)`、
  `api.ext.nexusGetModFiles(gameId, modId)`（返回 `IFileInfo[]`，字段是 V1 风格 `{ file_id, file_name, category_id, ... }`）。

> **建议**：列表/详情走 GraphQL（字段可控、少请求），文件列表也走 GraphQL；
> 只有当 GraphQL 出问题或用户未登录时，回退到 `api.ext.*`。

### 2.6 D｜下载：这是最需要「按官方姿势来」的一环

**✅ 可行，但必须走 `nxm://` 管道。**

先明确**不可行**的做法：

| 想法 | 结论 | 原因 |
| --- | --- | --- |
| 用 GraphQL 查下载直链 | ❌ | 没有这个查询；`ModFile.uri` 只是文件路径片段，`signedDownloadUrl` 仅 staff 可用 |
| 自己请求 `download_link.json` 拼 URL | ❌ | 免费用户拿不到；Premium 也需 `key`+`expires` 签名，且违反「不要自己实现下载」的设计 |
| 用 `webview` 打开 mod 页面点下载 | ⚠️ | 可行（`webviewTag: true`），但这就是「浏览器方案」，你要避免的正是它 |
| 直接写 Vortex 下载数据库 | ❌ | 破坏一致性，宿主会重算/清空 |

**正确的做法**（官方 `health_check` 就是这么写的，见 §8.3 代码）：

```ts
const nxmUrl = `nxm://${nexusDomain}/mods/${modId}/files/${fileId}`;
api.events.emit("start-download", [nxmUrl], { game: internalGameId, name, fileId, modId },
                undefined, cb, undefined, { allowInstall: false });
```

之后发生什么（源码 `nxmProtocol.ts`）：

- `nexus_integration` 注册了 `registerDownloadProtocol("nxm", nxmProtocol.resolve)`；
- **Premium**：用内置 nexus client 直接换出带签名的 CDN URL → 立即进下载队列；
- **免费**：进入 `FreeUserDLDialog`，引导用户在浏览器里点一次「Download with Vortex」，
  拿回带 `key`/`expires` 的 nxm 链接后继续下载；
- 下载进度、断点续传、MD5 校验、下载目录管理**全部由 Vortex 负责**，插件零负担。

**这条约束对产品的影响**：免费用户的「一键下载」实际是「一键跳转 + 一键继续」。
UI 上要提前说明（例如按钮旁标注 Premium 图标 / 提示条），否则会被当成 bug。

#### 2.6.1 免费用户到底发生了什么（源码实证 + 实测）

你的实测和源码完全对得上：**免费账号点下载时，Vortex 会调用 `opn()` 打开「系统默认浏览器」**
（所以是你的 Edge，不是 Vortex 内置浏览器），地址由 `nxmProtocol.ts:253` 拼出来：

```ts
// 源码原文（src/extensions/nexus_integration/nxmProtocol.ts:244-256）
onDownload: (inputUrl: string) => {
  …
  queued.awaitingLink = true;
  opn(`${NEXUS_BASE_URL}/${url.gameId}/mods/${url.modId}?tab=files&file_id=${url.fileId}&nmm=1`)
    .catch(() => null);
},
```

完整往返：

```
插件 emit('start-download', [nxm://…]) 
   → 宿主发现是「免费用户 + 无 key 的 mod 链接」(needsAuthorisedLink)
   → 挂起该下载（放进入 FreeQueue）+ 弹 FreeUserDLDialog
   → 点「Download」→ opn(https://www.nexusmods.com/<domain>/mods/<modId>?tab=files&file_id=<fid>&nmm=1)
   → 系统默认浏览器打开该文件页
   → 页面上点「Download with Vortex」→ 站点触发 nxm://<domain>/mods/<modId>/files/<fileId>?key=…&expires=…
   → OS 协议处理器把链接交给 Vortex → #deliverAwaitedLink() 匹配到挂起的那条 → 继续下载
```

关于你观察到的参数：

| 参数 | 含义 | 依据 |
| --- | --- | --- |
| `nmm=1` | 让站点使用「Download with Vortex/NMM」方式（页面会走 nxm 回传） | Vortex 源码里固定拼 `nmm=1`，用于免费用户授权回流 |
| `nmm=3` | 普通浏览器直接下载（不经过 Vortex） | 你的实测；Vortex 源码中不构造该值 |

**结论：网页 API 返回的从来不是「下载页」——这个跳转是 Vortex 自己发起的**（因为免费账号拿不到签名直链）。
所以插件里**不要自己打开 `nexusmods.com/...?nmm=1`**，交给 `start-download` 即可；
否则会出现「用户看到两个浏览器窗口 / 队列对不上」的问题。

两个额外收获（可直接用于开发）：

1. **免费流程可以本地强制复现**：环境变量 `FORCE_FREE_DOWNLOADS=yes` 会让
   `#canDownloadInApp()` 对所有无 key 链接返回 false，即使你是 Premium 也会走网站授权流程
   （源码 `nxmProtocol.ts:312`）——测试免费分支不用额外账号。
2. **挂起队列是全局的**：一次「取消」会把队列里所有挂起的下载一起 reject
   （`dialogHandlers.onCancel`），所以插件不要在用户取消后再自动重试，否则会反复弹窗。

### 2.7 E｜安装

**✅ 一条命令。**

```ts
api.events.emit("start-install-download", dlId, { allowAutoEnable: true }, (err, modId) => { … });
```

- `allowAutoEnable: true` 会自动启用 mod；
- 如果 mod 是 FOMOD（安装向导），Vortex 会正常弹出向导让用户选，这是**期望行为**，不要试图绕过；
- 装完后 mod 出现在 Mods 表，后续部署由 Vortex 处理。

## 3. 风险登记表（含缓解措施）

| # | 风险 | 等级 | 影响 | 缓解 |
| --- | --- | --- | --- | --- |
| R1 | GraphQL v2 是 WIP，字段/行为可能变 | 高 | 插件突然报错 | 网络层隔离成 `INexusTransport` 接口；所有查询集中在一个 `queries.ts`；解析用「字段可选 + 默认值」；关键错误给用户可读提示而不是堆栈 |
| R2 | 免费用户无法静默下载 | 高 | 体验落差 | 明确 UI 预期；检测 `isPremium(state)` 决定按钮文案；Premium 走全自动 |
| R3 | API Key 泄露 | 高 | 账号安全 | 只在内存持有；不打印；不写日志；不发第三方；错误上报时脱敏 |
| R4 | 请求过量 / 被限流 | 中 | 功能短暂不可用 | 搜索防抖 400ms；结果缓存 5–10 min LRU；`count ≤ 50`；不在 `onStateChange` 里发请求 |
| R5 | 成人内容门槛导致 `data: null` | 中 | 详情页空白 | 捕获 `ADULT_CONTENT_BLOCKED`，提示去站点改偏好；搜索层按用户偏好过滤 |
| R6 | 内部 gameId ↔ Nexus domain 混淆 | 中 | 下载落到错误游戏目录 | 单一转换工具函数；所有跨层传递用显式类型别名 `NexusDomain` / `VortexGameId` |
| R7 | Vortex 版本差异（`api.ext.*` 缺失） | 中 | 老版本崩 | 全部 `?.` 调用；`requireExtension('nexus_integration', '1.x')`；功能降级 |
| R8 | React 双实例 | 低 | 运行时崩溃 | 构建时把 react/react-dom/redux 设为 external |
| R9 | 合规：API 使用政策 | 中 | 插件被下架 | 不爬全站、不缓存整库、不重新分发数据、注明非官方；遵守 [API Acceptable Use Policy](https://help.nexusmods.com/article/114-api-acceptable-use-policy) |
| R10 | 大列表性能 | 低 | 卡顿 | 分页 + 图片懒加载 + `React.memo`；不一次拉 200 条 |
| R11 | 名称/商标 | 低 | 争议 | 命名用 "Nexus Mod Browser (unofficial)" 之类，说明非官方 |
| R12 | 分发渠道受限：Vortex 扩展页只收 game/theme/translation，`site-installer` 拒绝普通安装 | 中 | 用户装不上 | 主推 GitHub Release + 安装脚本；同步申请上架 `/site` 扩展区 |

```
│   ├─ SearchBar / FilterPanel / ModGrid / ModDetailDrawer / FileList      │
│   └─ useSelector(state)  ← session reducer（插件自己的 UI 状态）          │
│            │                                                             │
│            ▼                                                             │
│  NexusBrowserService  ── 编排 + 缓存 + 限流 + 错误归一化                  │
│            │                                                             │
│      ┌─────┴──────────┐                                                  │
│      ▼                ▼                                                  │
│  INexusTransport   DownloadBridge                                        │
│   ├ GraphQLTransport   ├ buildNxmUrl()                                   │
│   │  (node https +     ├ start-download                                  │
│   │   apikey)          └ start-install-download                          │
│   └ HostApiTransport                                                     │
│      (api.ext.*)                                                         │
└──────────────────────────────────────────────────────────────────────────┘
             │                                    │
             ▼                                    ▼
   api.nexusmods.com/v2/graphql         Vortex 内置下载/安装管道
```

**为什么要分 transport 两层**：
- `GraphQLTransport` 拿全量字段、一次请求（快），但依赖网络与 key；
- `HostApiTransport` 复用 Vortex 的 nexus client（自带登录态、限流、错误上报），但字段是 V1 风格、请求次数多；
- 运行时按「有 key + GraphQL 可用」优先，否则降级 —— 这同时解决了 R1 和 R7。

## 7. 下载/安装时序

```
用户                插件                       Vortex 宿主                站点/浏览器
 │  选文件           │                            │                        │
 ├──────────────────>│                            │                        │
 │                   │ 拼 nxm://domain/mods/M/files/F                      │
 │                   ├── emit('start-download') ─>│                        │
 │                   │                            ├─ NxmProtocol.resolve   │
 │                   │        ┌───────────────────┴──────────────────┐     │
 │                   │        │ premium: 换签名 URL → 直接入队        │     │
 │                   │        │ free   : 挂起 + 弹 FreeUserDLDialog   │     │
 │                   │        └───────────────────┬──────────────────┘     │
 │  （free 分支）     │<── FreeUserDLDialog ───────┤                        │
 │  点「Download」────┼────────────────────────────┼─ opn(…&nmm=1) ────────>│ 系统默认浏览器
 │                   │                            │                        │ 打开文件页
 │  页面点「Download with Vortex」 ────────────────┼───────────────────────>│ 触发 nxm://…?key=&expires=
 │                   │                            │<── OS 交给 Vortex ──────┤
 │                   │                            ├─ 匹配挂起队列 → 继续下载 │
 │                   │<── dlId ───────────────────┤                        │
 │                   ├── emit('start-install-download', dlId) ─>│          │
 │                   │                            ├─ 解压/装/启用           │
 │<── 新 mod 出现在 Mods 表 ───────────────────────┤                        │
```

> 关键点：free 分支的「浏览器」是**系统默认浏览器**（`opn()`），不是 Vortex 内置浏览器；
> 插件不要自己再打开一次，也不要假定跳转后会自动完成——UI 上应显示「等待浏览器授权…」状态。

**错误分支处理**

| 错误 | 来源 | 处理 |
| --- | --- | --- |
| `UserCanceled` | 用户在授权框点取消 | 静默（不报错），把按钮恢复可点 |
| `ProcessCanceled` | 宿主内部取消 | `api.sendNotification({type:'error'})` 简短提示 |
| `AlreadyDownloaded` | 同一文件已下载 | 直接复用已有 dlId（宿主已处理，插件只需吞掉） |
| 网络/HTTP 错误 | 下载阶段 | 宿主负责重试，插件不重复发 `start-download` |

**`src/bridge/download.ts`**

```ts
import { types, util } from "@nexusmods/vortex-api";

export async function downloadAndInstall(
  api: types.IExtensionApi,
  args: { domain: string; internalGameId: string; modId: number;
          fileId: number; fileName?: string; autoInstall: boolean },
): Promise<string | undefined> {
  const nxmUrl = `nxm://${args.domain}/mods/${args.modId}/files/${args.fileId}`;

  const dlId = await new Promise<string>((resolve, reject) => {
    api.events.emit(
      "start-download",
      [nxmUrl],
      { game: args.internalGameId, name: args.fileName, fileId: args.fileId, modId: args.modId },
      undefined,
      (err: Error | null, id?: string) => (err ? reject(err) : resolve(id!)),
      undefined,
      { allowInstall: false },
    );
  }).catch((err) => {
    if (err instanceof util.UserCanceled) return undefined;   // 用户取消授权 = 正常路径
    throw err;
  });

  if (!dlId || !args.autoInstall) return dlId;

  await new Promise<void>((resolve, reject) =>
    api.events.emit("start-install-download", dlId, { allowAutoEnable: true },
      (err: Error | null) => (err ? reject(err) : resolve())),
  );
  return dlId;
}
```

**`src/nexus/service.ts`（要点）**

```ts
class NexusBrowserService {
  private cache = new Map<string, { at: number; value: unknown }>();
  private inflight = new Map<string, Promise<unknown>>();

  async search(opts: ISearchOptions, key?: string) {
    const cacheKey = stableKey(opts);
    const hit = this.cache.get(cacheKey);
    if (hit && Date.now() - hit.at < 5 * 60_000) return hit.value as ISearchResult;

    if (this.inflight.has(cacheKey)) return this.inflight.get(cacheKey)!;  // 去重
    const p = this.transport.search(opts, key).finally(() => this.inflight.delete(cacheKey));
    this.inflight.set(cacheKey, p);
    const value = await p;
    this.cache.set(cacheKey, { at: Date.now(), value });
    return value;
  }
}
```

### 8.5 发布（有一个必须先知道的限制）

**官方扩展通道的现实情况**：Vortex 的「Extensions」页数据来自 Nexus v3 接口
`GET /v3/vortex/extensions`，只包含 **游戏扩展 / 主题 / 翻译** 三类
（`extension_manager/availableExtensions.ts`）；而且 `extension_manager/index.ts` 里的
`site-installer` 会**拒绝**把来自 `site` 域的包当普通 mod 安装
（报 `"Extensions have to be installed from the extensions page."`）。

所以「上传到 nexusmods.com/site 就能被一键安装」对**功能扩展**并不成立，除非先和官方谈进 feed。

**推荐的分发组合**：

| 渠道 | 用途 | 成本 |
| --- | --- | --- |
| GitHub Releases（zip）+ `install.ps1` | 主渠道：脚本自动复制到 `%APPDATA%\Vortex\plugins\nexus-mod-browser\` | 低 |
| Nexus `/site` 页面 | 曝光 + 更新日志；用户下载后手动放置 | 中（需审核） |
| 内测群/GitHub Issues | 反馈循环 | 低 |

**压缩包结构（若上架必须严格遵守）**

```
nexus-mod-browser.zip
├── index.js        ← 必须在根目录
├── info.json       ← 必须在根目录，version 与站点一致
└── (可选) assets/
```

> 最常见的审核失败：把文件全包在一个文件夹里（`nexus-mod-browser/index.js` ✗）。

**上架前准备**：上传到 `nexusmods.com/site` 的 **Modding Tools > Vortex Extensions** 分类，
只能有一个 Main File，`info.json` 的 `version` 必须与站点完全一致，名称不带版本号；
上传后 **2 小时内** Vortex 就会抓取（无需先等审核，之后是周期性复审），changelog 要准确，
README 写明「非官方 / 需登录 / 免费账号下载限制」。

> ⚠️ 注意「一游戏一扩展」规则：Vortex 每个游戏只展示一个扩展（取 endorsement 最多者）。
> 我们的插件不属于任何游戏，是否会被这个列表收录需要单独确认。

## 11. 结论与建议

**做，但按「Lite 浏览器」的定位做。**

理由：

1. **技术链路完全打通**：搜索（GraphQL）、页面（registerMainPage）、下载（nxm 管道）、安装（start-install-download）
   每一环都有官方 API 或官方先例，没有需要 hack 的地方。
2. **官方已经验证过同类产品**：内置的「Browse Nexus」页证明「在管理器里搜索 + 列表 + 下载」的交互模式成立，
   我们只是把对象从「合集」换成「单个 MOD」。
3. **真正的价值点**：省掉「打开浏览器 → 登录 → 点 Download with Vortex → 切回 Vortex」这 4 步，
   尤其对「边玩边挑 mod」的场景。

**不建议做的事**（既费力又容易踩雷）：

- ❌ 自建下载链接 / 自建 CDN 代理（拿不到签名，且违反 API 政策）
- ❌ 全站爬取或本地缓存整个 MOD 库（法律与政策风险）
